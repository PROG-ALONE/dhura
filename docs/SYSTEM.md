# ذُرى — التوثيق الشامل للنظام

> هذا المستند مرآة كاملة لبنية التطبيق وما أُنجز فيه، وُضِع تحسبًا لأي تعديل مستقبلي.
> آخر تحديث: أكتوبر 2026 — الإصدار التجريبي ١.

---

## ١) نظرة عامة

تطبيق ويب تقدّمي (PWA) عربي لتعلّم العلوم الشرعية، يعمل **في ملف واحد** `index.html` (~18.4 ألف سطر) مع `sw.js` (خدمة العاملة) و`manifest.webmanifest` وأيقونات وخطوط.

- **مسار تعليمي متدرّج:** مستويات (البراعم ← التأسيس ← مفاتيح العلوم ← المدارس والمذاهب ← المتون والعهد المدني ← الذروة)، في كل مستوى تبويبات علوم **تُفتح بالترتيب**، وحفظ القرآن يسير **بالتوازي**، واختبار شامل في آخر المستوى.
- **الحالة كلها في `localStorage`** بمفتاح واحد `mutun_app_v1` — لا خادم ولا حساب. المزامنة بين الأجهزة اختيارية ومشفّرة (GitHub gist).
- التطبيق يعمل بلا إنترنت بعد أول فتح (service worker).

## ٢) البنية التقنية لـ `index.html`

```
<head>
  سكربت الإطلاق (سطر 3): عند أول تشغيل يحذف mutun_app_v1 وdhura_sync وقاعدة dhura_rec
  then <style> شامل (سمات فاتحة/داكنة/كحلية، مصحف، براعم، طباعة…)
<body>
  <header id="hdr">   ← ترويسة علوية (renderHeader)
  <div id="app">      ← كل الشاشات
  <nav id="nav">      ← شريط تبويبات سفلي (renderNav)
  <div id="modal"> <div id="sheet"> <div id="toast">
  سكربت واحد ضخم (كتلة واحدة ~2.86 مليون حرف)
```

### قواعد ذهبية عند التعديل
1. **`KEY='mutun_app_v1'` لا يتغير.** علامات الإطلاق `dhura_launch` و`dhura_rst2` لا تمسح أي بيانات؛ تصفير التقدم لا يحدث إلا بطلب المستخدم من الإعدادات وبعد تأكيدين.
2. **نمط «التغليف المتتالي» (Wrapper Chain):** كثير من الدوال يُعاد تعريفها لاحقًا بنفس الاسم:
   `const _vHome40=vHome;vHome=function(){…return _vHome40()}` — الكود اللاحق في الملف يغلب السابق. عند البحث عن سلوك دالة يجب قراءة **كل** التعاريف من الأسفل للأعلى.
3. **كود ميت موجود:** مثّال blocks قديمة (مثل كتلة شاشة نتائج الامتحان القديمة ~8602-8660) تبدو نشطة لكن دوالًا لاحقة تحلّ محلها. لا تعتمد على ظاهر السطور وحدها.
4. بعد أي تعديل: `node check.js` يجب أن يطبع `ALL SCRIPTS PARSE OK` (يفحص كتل JavaScript المضمنة وعامل الخدمة `sw.js`).
5. **الاختبار على `localhost` فقط** (مثل `python3 -m http.server 8932`) لأن بيانات `localStorage` محصورة بالأصل (origin) — فلا تُمَس بيانات المستخدم الحية على GitHub Pages أبدًا.
6. `sw.js` يعمل **network-first** للمحتوى. ارفع رقم الكاش عند تغيير عامل الخدمة أو قائمة الملفات المخزنة مسبقًا؛ لا حاجة لذلك عند تعديل `index.html` وحده.
7. لا تُعدّل سطر الإطلاق ولا تمسح مفاتيح التقدم ضمن إصلاح أو تحديث اعتيادي. أي ترحيل أو إعادة ضبط يتطلب مسارًا صريحًا قابلًا للتراجع، ولا يُنفذ دون موافقة المستخدم.

## ٣) مفاتيح التخزين (localStorage)

| المفتاح | المحتوى | ملاحظات |
|---|---|---|
| `mutun_app_v1` | الحالة الكاملة `S` **للشخص النشط الحالي** (أيًا كان) | **لا يُغيَّر اسمه أبدًا** |
| `mutun_app_v1_<id>` | مخزّن حالة كل شخص **غير نشط** (نظام الأشخاص المتعددين) | يُملأ عند التبديل، ويُحذف عند حذف الشخص |
| `dhura_people` | قائمة الأشخاص `{list:[{id,name,rel}],active}` | مؤشر الشخص النشط |
| `dhura_sync` | `{device,pass,pak,at,on}` مزامنة مشفّرة PBKDF2+AES-GCM | `pak` لقطة مشفّرة |
| `dhura_grp` | مجموعة العائلة `{me,gist,token,pass,msgs…}` | تُمحى تلقائيًا مع حذف المجموعة |
| `dhura_launch` | علامة «شُغِّل مرة واحدة» — سطر الإطلاق | لا تُحذف؛ لا تمسح بيانات |
| `dhura_rst2` | علامة توافق قديمة من إعادة الضبط ٢.٠ | تُضبط مرة واحدة؛ لا تنفذ إعادة ضبط |
| `dhura_wn` | ما شوهد من «جديد» (الإصدار الحالي `WN_VER='2.1'`) | يُرفع لعرض الإشعار مرة أخرى |

**IndexedDB:**
- `dhura_voice` — تحميلات الصوت (VDB).
- `dhura_rec` — تسجيلات التسميع — لا تُحذف تلقائيًا؛ تُحذف فقط عند اختيار «تصفير التقدم».

## ٤) حالة المستخدم `S` (mutun_app_v1)

الحالة الافتراضية `defState()`:
```js
{settings:{perDay,hideTashkeel,theme,matn,modes}, p, notes, read, quiz,
 skipMem, treeQ, path, intro, profile, mt}
```
ومع الاستخدام تتضاف مفاتيح كثيرة — كلها تُمحى بزر «تصفير التقدم»:

| المفتاح | المعنى |
|---|---|
| `settings` | الإعدادات: الاسم، الحجم، الصوت، الأيام، التذكير، textScale… |
| `profile` | `{done,track,kid,parent,rel,g}` — اكتمال الترحيب، المسار، وضع الطفل |
| `mt` | إتمام دروس كل تبويب (`mt[itemKey]`) |
| `lvSeen` | المستويات المفتوحة رؤية (بوابة الفتح: اجتياز الامتحان + الحفظ) |
| `lvx` | حالة امتحانات المستويات: `{n rounds, last %, best, pass, ans, mist, fix}` |
| `crs` | تقدّم الدورات (`crs[cid].lv`) |
| `p` | بطاقات المراجعة المتباعدة (حِفظ) |
| `mist` | بنك الأخطاء `{key:{lv,c,due,at}}` — يُعالَج بالتكرار |
| `kid` | تقدّم رحلة البراعم `{done,stars,pt,mini,exam}` |
| `hz` / `hzx` / `hzAud` / `tj` | الحفظ: `{m:مرات, سماع…}` + الاختبار الإضافي + التسميع الصوتي |
| `mus` | المصحف: `{p page, mode, fs, lay.tj, kh ختمات, cur, log, bm, nt}` |
| `path` / `pathTour` | محطات المسارات + اجتياز جولة الشرح |
| `intro` / `treeQ` | مداخل المواد + أسئلة الشجرة |
| `fqu` | اختبارات الفقه (`FQST`) |
| `aml` | عمدة الأحكام (`AS()`) |
| `qs` / `spec` / `pdm` / `adk`… | أنظمة مساعدة (أسئلة، تخصص، أذكار…) |
| `log` / `ev` / `tm` | السجل: إنجازات كل يوم + أحداث بوقتها + دقائق كل قسم |
| `fam` / `me` | بيانات الأسرة (الأم/الأب/الطفل) وملفي داخل مجموعة العائلة |
| `plan` | خطة الدراسة `{days,rev,min,mode,setup}` |
| `ah` | تبويبات وتخصيص بطاقة «اليوم» |
| `notes` / `read` / `quiz` / `skipMem` | ملاحظات وقراءات واختبارات محفوظة |

**دوال مساعدة تُنشئ المقاطع عند الاستخدام:** `PS(pid)`, `CS(c)`, `KS0()`, `MS()` (المصحف)، `AS(id)`, `FQST(u)`, `AHS()`, `PLN()`, `LXS(k)`, `MIST()`… وهي تقرأ `S` في كل نداء، فلا مشكلة عند استبدال `S` كاملًا (زر التصفير، الاستيراد، تبديل الأشخاص).

## ٥) خريطة الشاشات (73 مسارًا)

`render()` يوجّه `route.v` إلى دالة العرض. أهمها:

- **الترحيب** `welcome` — قصة + اسم + (وضع الطفل) → `styFinish()` يضبط `profile.done`.
- **الرئيسية** `home` — ثلاث تبويبات: «اليوم» (افتراضي: مواقيت، مصحف، تقويم)، «الأذكار» `zkr`، «دراستي» (بوابة الخطة والمستويات).
- **المسار** `muslim` (بشحنة `{l:'D0'}`) — جبل المستويات + تبويبات المستوى `lvtab` + دروس `klesson`/`lesson` + مداخل `intro` + دورات `course` + مختبرات `tjlab/hjlab` + اختبار المستوى `lx` + شهادة `openCertJ`.
- **حفظ القرآن** `hz/hzrev/hzpick/hifz` — يسير بالتوازي دائمًا (مفتوح حتى قبل إتمام التبويبات).
- **المصحف** `mushaf` — أوضاع: صفحة/صفحتان/سكرول/تركيز آية، تجويد ملوّن، ختمة على الإيقاع، تفسير باللمس، علامات وملاحظات. **وضع ملء الشاشة ⛶** وزر رجوع ›.
- **السجل** `log` — تقويم الشهر + تفصيل اليوم + تقارير PDF/ملف.
- **الأدوات**: `mountain` (الطريق كاملًا)، `lib/hall` (المكتبة والخزانة المرتبة بالمستوى والتبويب)، `paths`، `fam` (ملفي والمجموعة والأشخاص)، `settings`، `tests`، `plan`، `spec`، `kid*` (رحلة البراعم)، `duas/zkr/zkb/adhkar`، `pdfs/book/read` (القراءة)، `practice/session` (المراجعة المتباعدة).
- **قراءة الكتب**: بطاقة الكتاب تعرض إجراءً واضحًا لفتح النص الكامل؛ إن كان النص مضمّنًا يُفتح داخل التطبيق أو للطباعة، وإلا تُعرض مصادر للنسخ المنشورة وخيار رفع PDF خاص بالجهاز. لا تُمس بيانات التقدّم عند تصفح المكتبة.

## ٦) أنظمة التقدّم والفتح (الفلسفة)

1. **داخل المستوى:** التبويب `t` لا يُفتح إلا بإنجاز `t-1` (`tabOpen`/`tabDone`)، والدرس `k+1` بعد `k`، وعناصر الدرس بالتتابع (`itemDone`).
2. **بين المستويات:** فتح المستوى `i` = اجتياز امتحان المستوى السابق **و** اكتمال منهج حفظه (`lvOpen` = `lvPassed(prev) && hzLvDone(prev)`، مع `S.lvSeen` كقفل أبدي بعد الفتح مرة واحدة).
3. **الامتحان يحفظ الإجابات ولا يعاد عند الخطأ:** يُسجَّل كل جواب في `x.ans`، وتُحفظ الدرجة في `x.last` و`x.best`. نسبة النجاح المستهدفة `LX_PASS=75`٪. بعد إتمام الجولة يمكن إعادة دراسة موضوعات الأخطاء ومراجعة أسئلتها أو العبور إلى المستوى التالي على أي حال؛ العبور لا يمحو الأخطاء، بل تبقى في `MIST()` ومراجعاتها اليومية. الإجابة الصحيحة عن خطأ لاحقًا ترفع الدرجة المحفوظة. `LX_N=150` سؤالًا.
   - **اختبارات الدرس داخل التبويب** (`pquiz` مع `pid=mtl:*`) تستهدف ٧٥٪، ولا تعيد الامتحان عند الخطأ؛ يظهر التعليل ثم يتابع المستخدم بقية الأسئلة. تُحفظ الإجابة ودرجة الاختبار، وفي النتيجة يمكن مراجعة الأخطاء أو إعادة دراسة الدرس، والمتابعة متاحة حتى دون بلوغ النسبة. اختبارات المسارات الأخرى تحتفظ بعتباتها الحالية، لكن لا تعيد الاختبار من البداية عند جواب خاطئ؛ تُراجع الأسئلة الخاطئة بعد الجولة.
   - **اختبار فهم المتون** لا يعيد الأسئلة من البداية أيضًا؛ يستهدف ٧٥٪، مع حفظ الدرجة ومراجعة الأسئلة الخاطئة أو إعادة الشرح أو المتابعة الصريحة. ويبقى اختبار شجرة النسب والحفظ (أو تخطيه) شرطًا مستقلًا لاكتمال محطة المتن. وفي اختبار الشجرة، الخطأ يعيد المحاولة في الموضع الحالي فقط ويحفظ المواضع المكتملة.
   - المراجعة اليومية الشاملة تعرض مستويات وأسئلة المحتوى المنجز فقط (`qPool`)، ولا تُظهر مستوى بلا أسئلة متاحة أو تفرض أسئلة من دروس لم تُنجز. وتُحافظ على صندوق الترسيخ (`QB`) لكل سؤال.
   - لا يُعاد ضبط حالة الاختبار أو تقدم الأشخاص عند تحميل التطبيق أو تغيير آلية الاجتياز.
   - تظهر المراجعة الشاملة على الرئيسية وداخل المستوى وفي «اختباراتي»، وتغطي جميع أسئلة ما أُنجز من المستوى؛ ومع إتمام المستوى تشمل محتواه المتاح كاملًا.
   - في أذكار الصباح أُبقي ورد «لا إله إلا الله وحده لا شريك له...» مئة مرة قبل «سبحان الله وبحمده» (رقم ١٩)، وحُذفت نسخة العشر مرات من هذا الورد لتجنب التكرار الظاهر. بقي ورد العشر في أذكار المساء. تُحفظ أعداد التكرار بمفتاح العنصر الأصلي كي لا يختلط تقدم المستخدم بعد تغيير الترتيب.
4. **حفظ القرآن:** `HZ_LV` يربط كل مستوى بسوره (D0:٦ سور، D1:٣٢…D4:٧)، و`hzDone(s)` تقرأ `HZS(s).m`، و`hzLvDone` تشمل الاختبار الإضافي `HZXS(k).pass` في المستويات المطلوبة (`hzOptional` بعد `HZ_REQ_LAST`).
5. **الشهادات:**
   - **شهادة المستوى** `openCertJ(k)` — **الشرط الجديد: اجتياز الامتحان + اكتمال منهج الحفظ** (`certHzReady` = كل سور `HZ_LV[k]` محفوظة). عند النقص يظهر زر مقفل يعرض «حفظت ٢٠ من ٣٢ سورة» ويشرح المطلوب.
   - شهادة الدورة `openCertC`، شهادات البراعم (مستوى/وحدات/كبيرة)، شهادة المسار `openCertJ` للجسر… كلها تُرسم على canvas ثم تُصدَّر PDF/PNG.
   - بيانات الشهادة من `certSummary(k)`: تبويبات ودروس وقصص ومتون وعدد السور المطلوب حفظها.

## ٨) الأشخاص المتعددون (أكتُب حديثًا)

- نظام حسابات مستقلة على الجهاز الواحد: **الأب، الأم، الأخ، الأخت…** كل واحد بحالته الكاملة المستقلة (تقدم، درجات، شهادات، حفظ، مصحف، سجل، إعدادات واسم).
- **التخزين**: الشخص الأول = `mutun_app_v1` (للتوافق العكسي)، والبقية `mutun_app_v1_<id>`، ومؤشّر `dhura_people`.
- **الواجهة**: لوحة «👥 أشخاص على هذا الجهاز» في الشاشة «ملفي» (`go('fam')` ← تبويب ملفي): تبديل، إضافة (اسم + صلة قرابة)، حذف بتأكيد.
- **التبديل** (`pplSwitch`): يحفظ حالة الشخص الحالي، محمّل حالة الآخر، يصفّر ذاكرة الجلسات في الذاكرة (`stateCachesReset`)، ثم يفتح الرئيسية أو الترحيب إن لم يُكمل الترحيب.
- عند فتح الصفحة: إن كان النشط ليس الشخص الأول، يُحمَّل مفتاحه تلقائيًا (بلوك تحميل مبكر بعد تعريف `PPL`).
- **ملاحظة**: مزامنة الأجهزة ومجموعة العائلة مشتركة عبر الأشخاص (تعتمد النشط الحالي)، وسطر الإطلاق يمحى `mutun_app_v1` فقط — أي أن «تصفير التقدم» يصفّر الشخص النشط وحده.

## ١٠) السجل — تقويم الأيام

- «السجل ← الأيام بالتفصيل» صار **تقويم شهر** (شبكة ٧ أعمدة): الأيام النشطة ملوّنة وتعرض دقائقها، والخارج عن المدة باهت، واليوم الحالي محدَّد بإطار ذهبي، ورأس الشهر يتنقّل ‹ ›.

## ١١) زر «تصفير التقدم» (Factory Reset)

الدالة `resetData()` في الإعدادات ← «المزامنة والنسخ الاحتياطي»:
1. **تحذير مزدوج** (نافذتان) مع تذكير بتصدير نسخة احتياطية.
2. `S=defState()` — الحالة تعود مطابقة للتثبيت الجديد حرفيًا (بما فيها الإعدادات والاسم).
3. مسح لقطة المزامنة `dhura_sync` (يبقى `device` فقط) + حذف قاعدة `dhura_rec`.
4. تصفير ذاكرة الجلسات في الذاكرة (درس/مراجعة/اختبار/بطاقات/خطة/قصة/جولة/ملء شاشة).
5. العودة إلى **شاشة الترحيب** — كل المستويات والتبويبات مقفلة، وجولة الشرح تبدأ من أولها.

### هذا الدفع (٣) — تدقيق الاتجاه RTL
- **بطاقات الأذكار** (`vAdhkar`): كانت البطاقة عند إتمام الذكر تخرج إلى اليمين (`translateX(+130%)`) والبطاقة التالية تدخل عموديًا — أي حركة من اليسار لليمين. الآن: البطاقة الحالية تخرج إلى **اليسار**، والتالية تدخل **من اليمين** (`dkinf` صارت `translateX(120%)`)، والسحب صار **يسارًا للتالي ويمينًا للسابق** (متوافقًا مع كتيّب الأذكار `zbSwipe`) مع تبديل موضع شارة «التالي» إلى اليمين و«السابق» إلى اليسار وتحديث نص التلميح. الرجوع معكوس تمامًا (يخرج لليمين ويدخل من اليسار `dkinb`).
- **حركات دخول كانت تأتي من اليسار فصارت من اليمين**: `figIn` (إطارات الأشكال)، `psIn` (بطاقات إعداد الخطة ونتائج التحليل)، وصفوف `hud-list .sci-row`.
- **`.ll-big`** (الحرف الكبير في «مخارج الحروف») صار يطفو من اليمين مع هامشه (`float:right;margin-left`).
- **نقاط الجمرات** `.hj-jmr i` تُملأ من اليمين (`direction:rtl`)، وزر «طباعة/حفظ PDF» في النسخة المطبوعة صار إلى اليمين (`text-align:right`).
- بلا أي مساس بمفاتيح التخزين أو التقدّم (`mutun_app_v1` وسواه كما هو).

### هذا الدفع (٤) — وصول التحديث إلى الجوال
- **المشكلة**: الجوال يبقى على نسخة قديمة مخزَّنة (كاش) فلا يظهر الإصلاح. الحل:
  - `sw.js`: **مراجعة صفحة التطبيق مع الخادم عند كل فتح** (`fetch(request,{cache:'no-cache'})` لطلبات التنقّل) بدل الاعتماد على الكاش حتى ينتهي، مع بقاء العمل دون إنترنت كما هو.
  - `index.html`: **إعادة تحميل تلقائية مرة واحدة** عند تفعيل عامل خدمة جديد (`controllerchange` + حارس `sessionStorage.dhura_up`) فلا يبقى الجوال على نسخة قديمة، ودون أي حلقة تحميل.
- **رفع رقم الإصدار إلى `APP_VER='1.2'`** ليظهر في «الإعدادات ← حول ذُرى» و«توقيع التطبيق» للتحقق من وصول التحديث (الإصدار ١.٢ = النسخة المُصلَّحة).


### هذا الدفع (٥) — إصلاحات الجوال (ركن الأذكار + اختبارات البراعم)
- **بطاقة التسبيح في ركن الأذكار** (`vZkr` → `ZKT==='home'`): كانت تُزال خطأً من الشبكة (`.zk-g`) بسبب سطر `b.remove()` في wrapper `vZkr` — الآن البطاقات الـ ٦ كلها تظهر: الصباح، المساء، بعد الصلاة، النوم، **التسبيح**، الأدعية.
- **اختبارات البراعم** (`tests` + `qPool`): تمت إضافة أسئلة دروس البراعم (٩٠ درسًا، ١٧٩ سؤالًا mcq/tf/order) إلى `qPoolOld()` مع تطبيع `kidQ()`، وإضافة مفتاح `k:` في `keyLevel()` ليعمل فلتر «البراعم» (`D0`). الآن عندما يكمل الطفل المستوى وتفتح «اختباراتي» تجد المراجعة بدلاً من «لا أسئلة بعد».

### هذا الدفع (٦) — إصلاح خيارات الاختبار (kid mcq)
- **العرض كـ `[object Object]`**: تطبيع `kidQ()` كان يمرر `o:[{t,ok}]` بينما `startQz`/`vQz` يتوقع **strings** (الإجابة الصحيحة أولاً). الآن `kidQ()` يضع الإجابة الصحيحة أولاً ويُبقي الخيارات نصوصًا — الخيارات تظهر بشكل صحيح، والquiz يعمل بالكامل (mcq/tf/order).
- شهادات الدورات `openCertC` وشهادات المسارات: هل تُقيَّد أيضًا بشروط حفظ؟ (حاليًا كما كانت).
- تصدير/استيراد النسخة الاحتياطية يشمل الشخص النشط فقط — هل نضيف «تصدير كل الأشخاص»؟
- **سحب المصحف وقارئ PDF ودروس البراعم** ما زال «سحب يمين = التالي» (حركة المحتوى نفسها فيه من اليمين لليسار أصلًا) — هل نوحّده إلى «سحب يسار = التالي» مثل كتيّب الأذكار وبطاقات الأذكار؟ (بانتظار قرار المستخدم؛ لم يُغيَّر).

### هذا التحديث (٢.١) — صون التقدم وتحسين المصحف
- أزيل الحذف التلقائي لبيانات المستخدم من علامات بدء التطبيق؛ تبقى بيانات `localStorage` و`IndexedDB` عند التحديث. التصفير متاح فقط بطلب صريح من المستخدم.
- حفظ التقدم والاستيراد وتبديل الأشخاص تُظهر الفشل، ولا يعتمد الاستيراد أو التبديل إذا فشل الحفظ.
- النسخة الاحتياطية توضح أنها تخص الشخص النشط، ويمكن استيراد النسخ القديمة ذات بنية الحالة المعتادة.
- عامل الخدمة يضمّن بيانات المصحف اللازمة دون اتصال، ولا يعيد صفحة HTML بدل ملف بيانات مفقود، ولا يحذف مخازن تطبيقات أخرى على الأصل نفسه.
- تبويب المصحف أقرب إلى الرئيسية، مع أدوات تكبير وتصغير ظاهرة وتحسين تباين ألوان التجويد في الوضعين الفاتح والداكن.
